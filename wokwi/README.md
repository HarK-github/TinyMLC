# Wokwi ESP32-S3 TinyML Simulation Demo

This project provides simulation files for a TinyML model compiled by **TMLC (TinyML Model-to-C Compiler)** for the **ESP32-S3-DevKitC-1** microcontroller on the **Wokwi simulator**.

> **Note**: These files are prepared for Wokwi simulation (`board-esp32-s3-devkitc-1`), but have not been simulated. Only `model.c` was compiled on the host PC using GCC (`gcc -std=c99 -Wall -Wextra -Wpedantic -Werror -c model.c`). It is not a physical hardware deployment.

---

## 1. Model Generation

The standalone ANSI C99 files (`model.c` and `model.h`) embedded in this project were generated by TMLC using symmetric per-tensor int8 weight quantization:

```bash
python main.py generate examples/tiny.tml --quantize int8 --out wokwi/
```

- **Architecture**: Tiny neural network (4 inputs $\to$ Dense(4, 8) + ReLU $\to$ Dense(8, 2) $\to$ 2 outputs).
- **Quantization**: Symmetric per-tensor int8 weights, positive float scale factor per Dense layer, float32 biases and activations.
- **Memory Footprint**: 96 bytes static flash weight storage, 40 bytes static working RAM (`buf_a` and `buf_b`), zero dynamic memory allocation (`malloc`/`free`).

---

## 2. Project Structure

- `sketch.ino`: Arduino C++ sketch reading comma-separated floats from Serial, validating input length against `MODEL_INPUT_SIZE`, measuring execution time with `micros()`, and invoking `model_predict`.
- `model.h`: Auto-generated C99 header declaring model macros (`MODEL_INPUT_SIZE`, `MODEL_OUTPUT_SIZE`) and `model_predict`.
- `model.c`: Auto-generated standalone C99 implementation containing int8 weight matrices, scale constants, and MCU-ready inference loops.
- `diagram.json`: Wokwi board definition specifying `board-esp32-s3-devkitc-1` and Serial monitor connections.
- `libraries.txt`: Library configuration (no external ML runtimes required).
- `README.md`: Project documentation and execution instructions.

## 3. How to Run in Wokwi

1. Open [Wokwi](https://wokwi.com) in your web browser.
2. Select **ESP32-S3** board (or create an ESP32-S3 project).
3. Upload / paste the files from this directory:
   - `sketch.ino`
   - `model.c`
   - `model.h`
   - `diagram.json`
4. Click the green **Start Simulation** button.
5. In the Serial Monitor (bottom-right panel), paste an input line and press `Enter`.

### Example Inputs to Paste

- **Valid input (4 comma-separated values)**:
  ```text
  0.5, -0.2, 0.8, -0.4
  ```
- **Another valid input**:
  ```text
  1.0, 0.0, -1.0, 0.5
  ```
- **Invalid input length (diagnostic test)**:
  ```text
  0.5, -0.2, 0.8
  ```
- **Invalid non-numeric input (diagnostic test)**:
  ```text
  0.5, abc, 0.8, -0.4
  ```

## 4. Expected Output Format

When pasting `0.5, -0.2, 0.8, -0.4`, the Serial Monitor prints:

```text
==================================================
TMLC ESP32-S3 Inference Demo (Model: Tiny)
Input Dimension : 4
Output Dimension: 2
Send comma-separated floats over Serial, e.g.:
  0.5, -0.2, 0.8, -0.4
==================================================
Predicted class: 0
Inference time: 4 us
Outputs: [-0.180772, -0.510108]
--------------------------------------------------
```

When pasting wrong input dimensions (e.g. 3 inputs instead of 4):

```text
Error: Input count mismatch. Expected 4 values, got 3
```

When pasting non-numeric text:

```text
Error: Invalid numeric input token 'abc'
```

## 5. Current Limitations

- **Simulated Environment**: Timing measured via `micros()` inside Wokwi reflects simulated CPU cycles of the virtual Xtensa LX7 core and may differ from physical silicon due to host instruction scheduling, flash wait-states, and memory bus latency.
- **Serial Parsing Latency**: String tokenization in Arduino C++ incurs overhead; in production embedded systems, inputs are typically received directly into float arrays from sensor DMA or ADC buffers.
- **Model Scope**: This demo runs the 4-8-2 Tiny model. For larger models (e.g., MNIST 784-128-64-10), ensure Serial input buffers are sized appropriately to stream 784 floats.
